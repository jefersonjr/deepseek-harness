# Agent Note：Bedrock 自适应代理恢复

Status: implemented

[English](2026-09-15-bedrock-adaptive-proxy-failsafe.md) | 中文

## 问题

部署环境观测到 100 KB 时返回 HTTP 403，推理 246 秒后返回 HTTP 502，而 82 秒请求成功。这些测量确定了大小和时长限制的存在，却未确定精确阈值。字符上限会拒绝有用的必需上下文，且无法衡量传输字节；仅限制输出 token 也不能限制推理耗时。

## 决策

本记录部分取代 [Bedrock profile 与 cmd](2026-09-14-bedrock-failsafe-cmd.zh.md) 中的字符预算及网关恢复决策。原记录保留 AWS profile 优先级、精简 preset 和 Windows cmd 行为。Normal Bedrock 保持普通传输行为。

Failsafe 按序列化 SDK 输入的 UTF-8 字节计数，包含 base64 二进制内容，并在传输前检查最终 HTTP 正文。可配置的初始上限为 80,000 字节和 512 输出 token，下限为 128 token。每次尝试具有包含流式传输的 75 秒绝对期限。请求和输出限制是独立控制。

502 或本地尝试期限到期先将输出减半，再在 token 下限处缩减输入目标。403 仅在配置的消息模式识别出大小拒绝时缩减输入；AWS 授权失败仍为终止错误。输入恢复以实际失败请求大小为依据。必需指令、工具 schema、当前用户输入及活动工具参数绝不回退到缩减目标以上，也不被静默截断。

每次尝试负责取消并等待传输结束后才重试。Failsafe 禁用 SDK 原生及外层提供方重试，包括外层 `always` 策略。重试次数、续写次数、总尝试次数和总时长共同限制一次生成。已完成文本部分在后续纠正重试中保留；失败部分输出和不完整工具参数不传给消费者或执行器。

成功纠正得到的较小上限按适配器、路由配置标识和模型保留，具有可配置过期时间。并发恢复保留较小限制。配置重载、过期或进程重启恢复配置的起始上限。学习仅存在于进程内，绝不自动提高上限。持久交换记录包含字节／token 上限、状态、耗时、首个内容延迟和失败分类；旧字符预算记录仍可读取。已移除字符设置会报错并明确说明字节设置迁移方法。

## 考虑过的替代方案

**将每个 403 视为大小拒绝。** AWS 用 403 表示授权失败。重试不能修复凭据或权限，还会错误学习代理上限。

**仅调整 max_tokens 或在收到块时重置计时器。** 两者均无法限制总推理时长。绝对期限在收到内容时保持有效，取消会等待所拥有的传输结束。

**二分查找最大可用预算。** 输出延迟取决于模型、输入和负载。向上探测会主动承担失败请求风险；保守缩减加过期机制提供可预测恢复，不宣称找到精确最优上限。

**持久化单个共享学习值。** 端点、AWS profile 和模型行为各异。实例内路由／模型状态避免无关流量继承缩减，也避免新增持久设置所有者。

## 影响

缩减上下文会丢失细节，必需输入仍可能在本地失败。较低输出下限可能无法容纳大型工具参数，任务需要更小的完整操作。总期限停止本地工作，但不能证明远程服务已停止计费或推理。仅返回通用 403 的代理需要可识别的大小错误消息才能启用自动大小恢复。

验证覆盖 UTF-8/base64 限制、短输入配合大型指令、必需数据保留、403 分类、502／期限恢复、取消、全局预算、学习隔离／过期及不完整工具调用。Loader 和 AWS 协议 HTTP fixture 验证 profile 签名、最终正文检查、重试前关闭传输以及 Normal 行为不变。两种 SDK 投影 fixture 保留新诊断。本地 fixture 不能证明真实 AWS 权限、SSO 续期或企业代理阈值。
